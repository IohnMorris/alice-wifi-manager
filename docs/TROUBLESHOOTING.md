# Диагностика

Менеджер не ведёт постоянный подробный журнал и не сохраняет stdout/stderr
`wpa_supplicant` на устройстве. Это сделано специально для защиты маленького
раздела данных и flash-памяти.

Единственный диагностический файл:

```text
/bkupgrade/data/ap_debug.log
```

Файл содержит только ошибки, таймауты и сбои отката, ограничен по размеру,
дедуплицирует повторения и является best-effort. Ошибка записи в него не должна
останавливать менеджер. Штатные переходы и состояние смотрите командами:

```sh
/usr/bin/alice-wifi-manager status
wpa_cli -i wlan0 status
ps | grep -E 'alice-wifi-manager|wpa_supplicant|dhcpcd|platformd'
test -S /var/run/alice-wifi-manager.sock
```

Если после обновления менеджер не запускается, не удаляйте recovery-каталог
`/bkupgrade/data/recovery-*`. Установщик сохраняет там предыдущие manager,
`wpa_supplicant`, init-скрипт и Wi-Fi-конфигурации и автоматически выполняет
rollback после неудачной health-проверки.

Если профили возвращаются после AP->STA, проверяйте основной конфиг и `.bak`:
они должны содержать одинаковый последний подтверждённый список сетей. При
необходимости восстановите старую версию через сохранённый recovery-каталог и
запустите `/etc/init.d/S99z-wifi-manager start`.
